# GitHub Discussion first post for General

The General category is for conversation that fits nowhere else: introductions, opinions, use cases, and chat about the project. A good first post makes the first reply easy by asking one friendly, specific question.

## Input required

- **The project** — name, purpose, and who it is for.
- **The community's stage** — brand new, or an established project adding Discussions.
- **The prompt** — what you want people to talk about.
- **Tone** — formal, friendly, or playful.

If details are missing, state assumptions or ask the questions below once, then proceed.

## Questions to ask first

Ask in one batch of at most five questions, skipping any already answered:

1. What is the project, and who uses it?
2. Do you want introductions, feedback on direction, or open chat?
3. Is there one question you would most like people to answer?
4. Which links belong in the post (docs, code of conduct, contributing guide)?
5. What tone fits the project?

## Method

1. Write a warm, specific title, such as "Say hello and tell us how you use Project X".
2. Open with one or two sentences welcoming readers and saying what the space is for.
3. Introduce yourself briefly as an example for others to follow.
4. Ask one concrete question that takes a sentence or two to answer, such as what they are building or what brought them to the project.
5. Point to the right category for other needs: Q&A for questions, Ideas for suggestions, Issues for bugs.
6. Link the code of conduct, if one exists.
7. Close by thanking readers and promising to reply to the first comments.

## Output format

A ready-to-paste Markdown post (see [[markdown]]):

- `Title:` one line.
- `Category:` General.
- Body: welcome, short self-introduction, one question, a where-to-go-for-what list.

## Output file

Save the finished post as plain text to `locales/en-us/communications/github-discussions/general.txt`, relative to the project root, creating the folders if needed. Put the title on the first line, a blank line, then the body. Tell the user the path.

## Ground rules

- Ask one question, not five. A long survey discourages replies.
- Do not invent community size, history, or achievements.
- Keep the tone inclusive and free of jargon the audience may not know.
- Use the serial comma and plain English.

## Self-check before answering

- Could a first-time visitor reply in under a minute?
- Is there one clear question?
- Does the post say where other topics belong?

## Common pitfalls

- **Generic openers** ("Welcome everyone!") with no question.
- **Too many questions**, so nobody answers any.
- **Sounding like a press release** instead of a person.
- **Using General for support questions** that belong in Q&A.

## Example prompt

> Write the first General post for the Discussions of my open-source note-taking app. I want people to introduce themselves and say what they use it for. Friendly tone.
